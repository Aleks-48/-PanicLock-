# PanicLock — ITU Hackathon 2026

Демонстрационный мобильный банк для сценария перевода под давлением. Next.js, TypeScript, Tailwind CSS и Lucide React отвечают за интерфейс. FastAPI проверяет PIN и проводит операции в SQLite. Валюта — тенге, суммы вводятся целыми числами. Все счета и получатели учебные.

## Запуск и защита проекта

Из корня репозитория выполните:

```sh
docker compose up --build -d
```

Откройте [мобильный банк](http://localhost:3080) и [экран оператора](http://localhost:3080/soc) в разных окнах. Получите ключ оператора в локальном терминале и вставьте его в поле Operator key:

```sh
docker compose exec -T bank cat /data/judge.key
```

Ключ генерируется при первом запуске. Он хранится в томе базы и в памяти открытой операторской страницы. Клиентский API не выдаёт этот ключ.

1. В мобильном банке нажмите **Transfer**. Оставьте тестового получателя и сумму **500 000 ₸**. Введите **1111**. Получатель получит 500 000 ₸, а доступный баланс отправителя уменьшится с 1 250 000 до 750 000 ₸. Оператор увидит событие SETTLED.
2. Нажмите **Back to home → Reset demo**. Создастся новый учебный счёт с тем же начальным балансом. Записи предыдущего прогона сохранятся в журнале оператора.
3. Повторите перевод с PIN **9999**. На телефоне появится такая же квитанция и тот же остаток. В SOC сумма зачислений останется прежней, карантин увеличится на 500 000 ₸. Новые записи HOLD_DURESS, MOCK_PUSH и MOCK_SMS связаны одним номером перевода. Денежные показатели SOC суммируются по всем учебным сессиям.
4. Обновите страницу или перезапустите контейнеры. Остаток, история платежей и инциденты сохраняются. Операторская страница опрашивает банк раз в секунду. На одном экране панель открывается кнопкой **SOC view**.

**Правило истечения срока.** Через 60 минут с момента тревожного перевода резерв снова доступен отправителю. Обработчик просроченных резервов работает каждые пять секунд и при чтении актуального состояния или следующем платеже. Возврат выполняется однократно, в том числе после простоя сервера. Получатель по этой операции средств не получает.

## Устройство MVP

- `app/page.tsx` — телефон, ввод реквизитов, PIN и единый экран квитанции. `app/client.ts` задаёт типы контрактов.
- `app/observer.tsx`, `app/soc` — авторизованный операторский экран, остаток резерва, сумма зачислений, последние 80 событий и время окончания карантина.
- `backend/main.py` — маршруты FastAPI, сессия устройства в HttpOnly cookie, отдельная авторизация SOC. Демонстрационная сессия открывает собственный счёт. Оба публичных тестовых PIN проверяются по отдельным солёным хешам Argon2id. Пять ошибок блокируют проверку на пять минут.
- `backend/banking.py` — списание доступной суммы, зачисление на учебный счёт получателя или резерв, возврат резерва. Одна транзакция охватывает проводку и журнал. Ключ идемпотентности привязан к отправителю и реквизитам.
- `backend/store.py` — счета, остатки получателей, платежи и события в SQLite. Номер получателя хранится в виде привязанного к счёту хеша и маски. Суммы хранятся как целые KZT.
- Платёжный шлюз эмулируется записью в реестр получателей. Push в SOC и SMS доверенному контакту эмулируются структурированными записями с адресатом, номером операции и временем. Внешние сообщения и обращения в полицию не отправляются.

## Проверки и эксплуатация демо

```sh
docker compose exec bank python -m unittest discover -v
docker compose ps
docker compose down
```

Тесты используют временные базы и управляемые часы. Проверяются квитанции обоих сценариев, зачисление, оповещения, недостаток средств, повтор запросов, конкурентное списание, сохранение резерва после перезапуска и возврат через час.

Compose публикует только интерфейс на loopback. Порт можно выбрать через PANICLOCK_PORT. Данные и ключ SOC переживают обычный docker compose down в именованном томе ledger. Версия предназначена для локальной защиты на синтетических реквизитах. Открытая регистрация демосессий и известные демонстрационные PIN подходят для этой среды. Для банковского пилота потребуются собственные идентификация клиента и операторов, управление ключами и согласованный регламент реагирования.
