# PanicLock

PanicLock — сервис на FastAPI, который показывает клиенту одинаковую квитанцию при обычном и тревожном PIN. При обычном PIN деньги переходят получателю. При тревожном PIN деньги остаются на счёте отправителя, а оператор банка получает скрытое оповещение.

Демонстрация занимает несколько минут. Понадобятся Python 3.9 или новее, curl и терминал macOS или Linux. Все суммы указаны в центах США. Балансы и сообщения для локальной панели службы безопасности (SOC) хранятся в SQLite.

[Репозиторий PanicLock на GitHub](https://github.com/Aleks-48/-PanicLock-)

## 1. Подготовьте окружение и счета

Откройте терминал в папке с файлами `app.py`, `provision.py` и этим README. Все команды ниже выполняйте в одном окне. Для демонстрации создаётся новая временная база, поэтому пример можно повторить с исходными балансами.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-test.txt
export PANICLOCK_DB="$(mktemp -d)/paniclock.sqlite3"
export PANICLOCK_OPERATOR_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
python provision.py alice 10000
python provision.py bob 250
```

Каждая из последних двух команд попросит ввести сначала обычный PIN (`Normal PIN`), затем тревожный (`Duress PIN`). При вводе символы скрыты. Для примера используйте следующие данные.

| Счёт | Начальный баланс | Обычный PIN | Тревожный PIN |
| --- | ---: | --- | --- |
| alice | 100,00 $ | 1111 | 9999 |
| bob | 2,50 $ | 2222 | 8888 |

## 2. Запустите API

```sh
uvicorn app:from_env --factory --host 127.0.0.1 --port 8000 &
SERVER_PID=$!
API=http://127.0.0.1:8000/api/v1
```

Дождитесь сообщения `Application startup complete`. Сервер работает в фоне. Описание запросов доступно в [локальном Swagger UI](http://127.0.0.1:8000/docs).

Скопируйте в терминал три функции. Первая получает токен для Alice по PIN, вторая переводит указанное число центов Бобу, третья читает фактические балансы из демонстрационной базы.

```sh
login() {
  curl -fsS "$API/auth/verify" -H 'Content-Type: application/json' \
    -d "{\"account_id\":\"alice\",\"pin\":\"$1\"}" |
    python -c 'import json, sys; print(json.load(sys.stdin)["access_token"])'
}

transfer() {
  curl -sS -w '\nHTTP %{http_code}\n' "$API/transfer" \
    -H "Authorization: Bearer $1" \
    -H "Idempotency-Key: $(python -c 'import uuid; print(uuid.uuid4())')" \
    -H 'Content-Type: application/json' \
    -d "{\"recipient\":\"bob\",\"amount_minor\":$2}"
}

balances() {
  python - <<'PY'
import os, sqlite3
with sqlite3.connect(os.environ["PANICLOCK_DB"]) as db:
    for account, cents in db.execute("SELECT id, balance FROM accounts ORDER BY id"):
        print(f"{account}: {cents} центов")
PY
}
```

## 3. Проверьте обычный PIN

```sh
NORMAL_TOKEN=$(login 1111)
transfer "$NORMAL_TOKEN" 1000
balances
```

**Ожидаемый результат.** API возвращает HTTP 200, поле `status` равно `SUCCESS`, а `message` — `Transaction Successful`. Перевод на 10,00 $ проведён. У Alice осталось **9000** центов, у Bob стало **1250**.

## 4. Проверьте тревожный PIN

```sh
PANIC_TOKEN=$(login 9999)
transfer "$PANIC_TOKEN" 8000
balances
```

**Ожидаемый результат.** Клиент видит HTTP 200 и ту же надпись `Transaction Successful` для перевода на 80,00 $. Балансы по-прежнему **9000** и **1250** центов. Проверку с обычным PIN важно выполнить первой, поскольку тревожный перевод блокирует исходящие операции Alice на 60 минут во всех её сессиях.

## 5. Посмотрите событие глазами оператора

```sh
curl -fsS "$API/security/dashboard" \
  -H "Authorization: Bearer $PANICLOCK_OPERATOR_TOKEN" | python -m json.tool
```

В `active_alerts` найдите событие со статусом `HOLD_DURESS` и уровнем `CRITICAL`. Его `transfer_id` совпадает с `transaction_id` из второй квитанции. Поле `intercepted_amount_minor` равно **8000**, а событие также присутствует в `high_risk_events`.

В этом примере оценка риска равна **95** баллам: 80 за тревожный PIN и 15 за сумму строго выше 70% текущего баланса (8000 из 9000 центов). Если между переводами прошло меньше 60 секунд, добавляются ещё 10 баллов и оценка достигает **105**. Порог высокого риска — 80 баллов.

## Автотесты и остановка

```sh
python -m pytest -q
kill "$SERVER_PID"
```

Тесты создают отдельные базы. Они проверяют квитанции и балансы, повторные запросы, права оператора, откат при сбое доставки оповещения и окончание блокировки. Ждать час не требуется: в тестах время задаётся программно.

## Детали API

- `POST /api/v1/auth/verify` принимает идентификатор счёта и PIN в виде строк. Сервер проверяет оба хеша Argon2id и выдаёт токен на 15 минут. Признак тревоги хранится на сервере. После пяти последовательных неверных попыток вход временно блокируется на пять минут.
- `POST /api/v1/transfer` определяет отправителя по токену. Для нового перевода нужен новый UUID в заголовке `Idempotency-Key`. Функция `transfer` выше создаёт его при каждом вызове. Чтобы повторить **тот же запрос** после сетевого сбоя, клиент передаёт исходный UUID и те же параметры. Он получит исходную квитанцию. Изменение суммы или получателя при том же ключе возвращает HTTP 409.
- Новый перевод с тревожным PIN запускает или продлевает блокировку на 60 минут. После её окончания обычные переводы снова проходят. Ранее задержанные операции автоматически не исполняются.
- `GET /api/v1/security/dashboard` принимает отдельный токен оператора. Список активных оповещений учитывает срок блокировки, записанный для каждого события. История событий высокого риска сохраняется. Временные метки оператора указаны в секундах Unix.
- Сумма перехваченных переводов учитывает полную сумму каждой задержанной операции с отдельным ключом и может превышать баланс. Критическое событие и сообщение для локальной панели записываются в одной транзакции. Для демонстрации внешняя платёжная сеть и внешний вебхук не требуются.
